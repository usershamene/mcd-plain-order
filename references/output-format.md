# 输出消息格式规范（Output Format Spec）

> 适用范围：麦麦明白点（mcd-plain-order）所有面向用户的消息，尤其是「极速点单」主链路的最终回执。
> 实现：`scripts/render.py`（确定性模板，模型只填结构化数据，不负责格式）。
> 配套：`references/design-standards.md`（金额三行、大白话等适老/省心标准）。

---

## 1. 为什么要有这份规范

极速点单的核心承诺是「说一句话，明明白白点好」。如果用户拿到的是一段长短句混杂、重点淹没在铺垫里的文字，承诺就落空。

输出格式不是"美化"，是**确定性工程**：模型擅长理解意图、组装数据，但不擅长稳定地控制排版。把格式交给代码（`render.py`），才能保证每一次输出都一致、克制、信息密度高。

---

## 2. 三大原则

| 原则 | 含义 | 反例 |
|---|---|---|
| **先给答案** | 第一条有效信息就是点单结果，不写"为您查询到以下结果"之类前戏 | "您好！我帮您查询了一下，发现可以这样点……" |
| **图标即标签** | 用 🍔/🆕/🎫/⭐/👉 当段标题，省去"以下是新品提醒"废话 | "下面给您一些新品提醒：……" |
| **不留空段** | 某段没内容就不显示，不凑数、不占位 | 永远显示"🎫 券提醒：暂无" |

**最少字、最多信息的三个具体手段：**
1. **数字优先**：金额给 `¥8.1`，不给"八块一"；紧迫度给"剩 82 分钟"，不给"快过期了"。
2. **清单化**：餐品、提醒都用 `·` 单行，不用成段叙述。
3. **省略主语与连接词**：块内不重复"您/这个/那个"，靠位置和图标表意。

---

## 3. 四段式结构（固定顺序）

```
[问候/上下文]          ← 可选，最多一行，仅在有价值时
🍔 为你推荐             ← 核心，必须有
🆕 新品                ← 可选，命中用户喜欢时标"你喜欢的"
🎫 券提醒              ← 可选
⭐ 积分                ← 可选
👉 确认下单？           ← 行动召唤，写操作必带
```

**顺序不可调换**：用户最先要看的是"我点了啥、花多少"，提醒是补充，确认是收尾。

**段间区分靠两层**：① 每段以「图标 + 短标签」做标题；② 段与段之间空一行。两层足够，不用再加边框或分隔线（避免视觉噪音）。

---

## 4. 各段规范

### 4.1 问候 / 上下文（可选）
- 仅当时间或场景能增加价值时给，例如通勤时段、节假日。
- 最多一行，不追问、不寒暄。
- 例：`👋 早，通勤路上？`

### 4.2 🍔 为你推荐（核心，必须有）
- 标题用「为你推荐」而非「你的点单」：本助手是**给建议**，不是替用户认定"这就是你点的"。语气软、不强制，用户仍可改。
- 标题后括号附 **取餐方式** 与 **预计时间/到店即取**。
- 餐品逐行 `· 名称 ×数量`。
- 金额永远**三行**：原价 / 优惠（-¥X，括号内写优惠来源如"早餐卡"）/ 实付。
- 例：
  ```
  🍔 为你推荐（到店自取 · 预计 12:30 到店即取）
  · 大脆鸡扒麦满分组合 ×1
  · 热豆浆 ×1
  ────────────
  原价 ¥13.5
  优惠 -¥5.4（早餐卡）
  实付 ¥8.1
  ```

### 4.2.1 极速点单方案块（尖入口，未选具体餐品时）

当用户走「极速点单」入口、尚未选定餐品时，🍔 块先给出**方案**（选店 + ETA + 预约），由 `render.render_fast_plan()` 生成。用户确认方案后再进入 4.2 的餐品/金额块。

- 标题：`🍔 极速点单（<方式> · 预计 N 分钟<到店/送达>）`，方式与标题见 `fast_order._METHOD_LABEL`（到店自取/得来速/麦乐送）。
- 第二行：最近门店名 + 距离（`· 最近门店：名称（605 米）`），仅取营业中且支持预约的、distance 最小者。
- 第三行（到店自取/得来速）：`· 预约到店：yyyy-MM-dd HH:mm（<时段>时段，到店即取）`；落在时段间隙则显示「已顺延至本时段起点」。
- **麦乐送不显示第三行**（无门店预约概念），标题已给"预计 N 分钟送达"，仅保留派单门店行。
- 例（到店自取）：
  ```
  🍔 极速点单（到店自取 · 预计 9 分钟到店）
  · 最近门店：示例得来速餐厅（605 米）
  · 预约到店：2026-10-11 09:14（早餐时段，到店即取）
  ```
- 例（麦乐送）：
  ```
  🍔 极速点单（麦乐送 · 预计 9 分钟送达）
  · 最近门店：示例得来速餐厅（605 米）
  ```

### 4.2.2 与点单块同框时降级为「📍 取餐安排」

当极速方案**伴随完整点单**（用户已选定餐品、进入执行流，`workflow.run_fast_order` 的产出）时，
方案不再独立成 🍔 块，而是作为「🍔 为你推荐」下方的 **📍 取餐安排** 子块，避免两个 🍔 撞脸、重复方式与 ETA 头。

- 触发：`render.render_message` 检测到同时存在 `order` 与 `fast_plan` 时，对 `fast_plan` 以 `detail=True` 渲染。
- 子块仅含门店 + 预约行，方式与 ETA 已由推荐块头部承担。
- 例（到店自取·已下单）：
  ```
  🍔 为你推荐（到店自取 · 预计 9 分钟到店）
  · 板烧鸡腿堡套餐 ×1
  · 薯条 ×1
  ────────────
  原价 ¥33
  优惠 -¥6
  实付 ¥27

  📍 取餐安排
  · 最近门店：示例得来速餐厅（605 米）
  · 预约到店：2026-10-11 09:14（早餐时段，到店即取）
  ```

### 4.3 🆕 新品（可选）
- 来自 `query-meals` 过滤 `tags` 含"上新/清爽上新"（数据源 `scripts/newitems.py`）。
- 命中用户画像"喜欢"的品类时，在该行末尾追加「 · 你喜欢」，标题保持中性（避免把不喜欢的也归入"你喜欢的"）。
- 单行：`· 名称 ¥价格（上新）` 或 `· 名称 ¥价格（上新） · 你喜欢`。
- 例：
  ```
  🆕 新品
  · 蓝莓爆爆珠麦旋风 ¥16（上新） · 你喜欢
  · 灰焰圆筒 ¥5（上新）
  ```

### 4.4 🎫 券提醒（可选）
- 仅提示**即将过期**的券（按距窗口关闭的分钟数，数据源 `scripts/reminders.build_coupon_reminder`，复用 `coupons.urgent`），不罗列全部。
- 带紧迫度：`· 标题 · 剩 82 分钟`。
- 不写"快抢""限时"等诱导词（见 design-standards）。
- **兴趣匹配（已实现）**：给 `build_coupon_reminder` 传 `profile` 时，命中用户画像"喜欢"品类的券会被打 `liked`，渲染层在该行末尾加「 · 你喜欢」。例：用户说过喜欢薯条 → 「中薯条买一送一」标"你喜欢"。属兴趣匹配，非推销——用户没说过喜欢的不强行提。
  - 例：
    ```
    🎫 券提醒
    · 中薯条买一送一 · 剩 82 分钟 · 你喜欢
    · 火腿扒堡早餐两件套 · 剩 30 分钟
    ```

### 4.5 ⭐ 积分（可选）
- 数据源 `query-my-account`（可用积分）+ `mall-points-products`（可兑换项，取 `point>0` 且在售）。
- 一行说清：当前积分；能换则给"可换「Y」"，不能换则给"还差 X 分换「Y」"（取差距最小的目标）。
- 例：
  - `⭐ 积分 · 当前 180 分，可换「板烧鸡腿堡两件套」`
  - `⭐ 积分 · 当前 30 分，还差 20 分换「香芋派」`

### 4.6 👉 确认下单（行动召唤，写操作必带）
- 写操作前必须出现，且必须含**可撤销提示**（10 分钟内可取消）。
- 例：
  ```
  👉 确认下单？
  · 下单后 10 分钟内可取消（回复「确认」）
  ```

## 5. 用词红线（来自 design-standards）

| 不用 | 改用 |
|---|---|
| 折扣 / 抵扣 | 优惠 |
| 核销 / 使用券 | 用了券 / 优惠 |
| 随心配 / 券包 | 优惠套餐 / 优惠券 |
| 限时 / 仅剩 / 快抢 | 不出现（无诱导） |

---

## 6. 反例（禁止）

```
❌ 您好！我帮您看了一下，您附近门店今天有这些可以点，
   另外您卡包里有一张券快过期了，还有几个新品上市，
   下面我给您列一下……（铺垫 3 行，重点淹没）

❌ 🎫 券提醒：暂无可用券（空段占位）

❌ 您本次消费享受了折扣优惠，已为您核销优惠券（专业黑话）
```

---

## 7. 实现约定

- 所有消息必须经 `render.py` 产出；模型产出的是 `render_message(result)` 的入参（`result` 字典），不是最终文字。
- `render.py` 对缺失字段容错（缺价不崩、缺段不显），测试见 `tests/test_render.py`。
- 新增任何"段"都先在本文档登记顺序与图标，再在 `render.py` 加对应函数。
