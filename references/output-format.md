# 输出消息格式规范（Output Format Spec）

> 适用范围：所有面向用户的消息。
> 实现：`scripts/render.py`（确定性模板）；合规入口 `scripts/reply.py`；校验 `scripts/validate_reply.py`。
> 配套：`references/design-standards.md`（金额三行、大白话等标准）。

---

## 0. 一句话

**每条消息 = 一个主块 + 可选补充段 + 一句下一步。** 格式由代码产出，模型只填结构化数据。

---

## 1. 三大原则

| 原则 | 含义 | 反例 |
|---|---|---|
| **先给答案** | 第一条有效信息就是结果，不写"为您查询到" | "您好！我帮您查询了一下……" |
| **图标即标签** | 用图标当段标题，省去"以下是……" | "下面给您一些新品提醒：" |
| **不留空段** | 没内容就不显示，不凑数 | 永远显示"🎫 券：暂无" |

三个具体手段：**数字优先**（`¥8.1`、`剩 82 分钟`）、**清单化**（`·` 单行）、**省略主语与连接词**。

---

## 2. 消息类型（8 类）

| 类型 | 主块图标 | 触发 | 渲染函数 |
|---|---|---|---|
| 点单 | 🍔 | 用户要下单 | `render_order` |
| 查门店 | 🏪 | "附近有麦当劳吗" | `render_stores` |
| 查菜单 / 商品 | 🍟 | "有什么 / 冰淇淋怎么卖" | `render_menu` |
| 新品 | 🆕 | "有什么新品" | `render_new` |
| 券 | 🎫 | "我有什么券" | `render_coupon` |
| 方案对比 | 🍔 方案对比 | "给我几个方案" | `render_compare` |
| 回执 | ✅ | 下单成功 | `render_receipt` |
| 错误 / 确认 | ⚠️ | 失败 / 歧义 | `render_error` |

---

## 3. 通用骨架（顺序固定）

```
[👋 问候]                    ← 可选，最多 1 行
<主块：🍔 / 🏪 / 🍟 / ✅ / ⚠️>   ← 必须，且只 1 个
[🆕 新品] [🎫 券] [⭐ 积分]      ← 可选，按此顺序
👉 下一步                     ← 必须，1–2 行
```

段间空一行；不用边框或分隔线（视觉噪音）。

---

## 4. 各类型模板

### 4.1 点单 🍔

```
🍔 为你推荐（<方式> · <ETA>）
· <商品> ×<数量>
────────────
原价 ¥<原价>
优惠 -¥<优惠>（<来源>）      ← 优惠为 0 时省略
实付 ¥<实付>

📍 取餐安排
· 最近门店：<名称>（<storeCode> · <距离> 米）
· 预约到店：<yyyy-MM-dd HH:mm>（<时段>时段，到店即取）
```

### 4.2 查门店 🏪

一行一家店，四个关键属性用 ` · ` 分隔；**不要宽表格**。

```
🏪 附近门店（5 家 · 按距离）
· <名称>（<storeCode> · 605 米 · 06:00–23:00 · 可预约）
· <名称>（<storeCode> · 1981 米 · 07:00–22:00 · 可预约）

👉 选一家，我帮你看菜单
```

### 4.3 查菜单 🍟

```
🍟 菜单 · <门店>（<storeCode>）
· <商品> ¥<价格>
· <商品> ¥<价格>（<标签>）

👉 报个名字，我算价
```

### 4.4 新品 🆕

```
🆕 新品（<N> 样）
· <商品> ¥<价格>（上新）
· <商品> ¥<价格>（上新） · 你喜欢

👉 想尝哪个？
```

### 4.5 券 🎫

```
🎫 券（5 张 · 今天可用 0）
· <标题> · ¥<优惠价> · <可用日/时段>
· <标题> · ¥<优惠价> · <可用日/时段>

👉 明天早餐最划算
```

### 4.6 方案对比 🍔 方案对比

每个方案 **1 行金额 + 1 行商品**，不展开成长段落。

```
🍔 方案对比（到店自取）
A. 鸡薯双全盒 + 灰焰圆筒 · 实付 ¥20.9
B. 蘸酱麦麦脆汁鸡 + 圆筒×2 · 实付 ¥21.9
C. 龙焰鸡腿堡 + 灰焰圆筒 · 实付 ¥29

👉 回复字母选一个
```

### 4.7 回执 ✅

固定 5 行，不再追加自由文本。

```
✅ 已下单 · <门店>（<storeCode>）
· 订单号：<orderId>
· 付款：<payH5Url>
· 截止：<yyyy-MM-dd HH:mm>（<N> 分钟内可取消）
· 实付 ¥<实付>
```

### 4.8 错误 / 确认 ⚠️

```
⚠️ <一句话说明>
· <原因原文>
👉 <下一步>
```

例：
```
⚠️ 门店编码不对
· 「3330716」是柳西咏归菜场，不是长兴路
👉 回「用柳西」或「换长兴路」
```

## 5. 通用规则（硬）

1. **一屏一条、只一个主块**；补充段固定顺序 `🆕 → 🎫 → ⭐ → 👉`。
2. **头行公式** `<图标> <名词>（<关键数字/限定>）`，≤1 行。
3. **正文 `·` 单行**；只有"≥3 项 × ≥3 属性"才用表格。
4. **金额**：`原价 / 优惠 -¥<X> / 实付`；优惠为 0 时省略优惠行；**统一 1 位小数**（整数不带小数）。
5. **门店**：`名称（storeCode · 距离 米）`；**下单 / 回执必须带 storeCode**。
6. **回执固定 5 行**，不再追加"两点说明"之类自由文本。
7. **长度预算**：查询类 ≤12 行；点单 / 回执 ≤18 行；超出就分条或只给 Top N。
8. **只允许登记的图标 / 段**；禁止 `🔗`、`订单号：`、`付款截止：` 等散装标题（回执里统一用 `· 订单号：` / `· 付款：` / `· 截止：`）。
9. **必须走代码**：最终文本由 `render.py` / `reply.py` 产出；模型只填 `result` 字典。

---

## 6. 用词红线

| 不用 | 改用 |
|---|---|
| 折扣 / 抵扣 | 优惠 |
| 核销 / 使用券 | 用了券 / 优惠 |
| 随心配 / 券包 | 优惠套餐 / 优惠券 |
| 限时 / 仅剩 / 快抢 | 不出现（无诱导） |

---

## 7. 反例（禁止）

```
❌ 您好！我帮您看了一下，您附近门店今天有这些可以点，
   另外您卡包里有一张券快过期了，还有几个新品上市……（铺垫淹没重点）

❌ 🎫 券提醒：暂无可用券（空段占位）

❌ 您本次消费享受了折扣优惠，已为您核销优惠券（专业黑话）

❌ 一条消息里出现 3 个 🍔 头（门店 / 新品 / 冰淇淋 / 点单各一个）
```

---

## 8. 实现与强制

| 层 | 工具 | 作用 |
|---|---|---|
| L1 路径最短 | `scripts/reply.py` | 传 `result` JSON，直接产出成品消息 |
| L2 自检 | `scripts/validate_reply.py` | 校验主块 / 金额 / storeCode / 长度 / 禁用词，机器可读 PASS/FAIL |
| L3 宿主 hook | `hooks/validate_reply_hook.py` | pre-send 拦截不合规输出（接线见 `references/enforcement.md`） |
| L4 度量 | `evals/format_compliance.py` | 对一批回复统计格式合规率 |

> 强制机制的现实边界与接线方式，见 `references/enforcement.md`。
