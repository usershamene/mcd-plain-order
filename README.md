# 麦麦明白点 · mcd-plain-order

> **说一句话，明明白白点好一餐。**
> 对话式麦当劳点餐助手，覆盖「选餐 → 省钱 → 算价 → 下单 → 取餐 → 售后」完整流程，并对齐工信部适老化设计规范。

本项目参加 [麦当劳程序员节创意开发大赛](https://github.com/M-China/mcd-developer-innovation-challenge)，作品形态为 **WorkBuddy Skill**。

> ⚠️ **仓库名与 Skill 名必须一致**。当前使用 `mcd-plain-order` 作为占位名，发布前请确认（可选替代：`mcd-clear-order`）。若改名，需同步修改 `SKILL.md` 的 frontmatter `name` 字段与下方安装路径。

---

## 它解决什么问题

点一份麦当劳，官方 App 已经能做。**所以这个 Skill 的价值不在"能点餐"，而在四件事：**

| # | 差异点 | 官方 App | 本 Skill |
|---|---|---|---|
| 1 | **编排** | 你得先自己决定到店还是外送 | 有配送地址自动走麦乐送，没有就走到店，**不用你说** |
| 2 | **对比** | 只能一单一单试 | 一次给 ≥3 个方案，每个价格都用官方接口**真实计价** |
| 3 | **明确** | 优惠、配送费混在一起 | 金额永远三行：**原价 / 优惠 / 实付** |
| 4 | **可逆** | 下单后自己找取消入口 | 下单回执主动写明「**10 分钟内可撤销**」 |

### 为什么选择"适老设计"而不是"只服务老人"

麦当劳消费主力是 20~35 岁；银发族点过外卖的仅 12.5%、能自行线上点餐的不足 20%——**把老人当作唯一人群，用户池撑不起来**。

但工信部适老化规范里的条目（大字号、无诱导付款、财务交易可撤销、不用专业词）**对所有人都有价值**。

所以本项目的定位是：**面向全体消费者，用适老标准做设计。** 详细的数据论证见调研报告。

## 目标用户

| 层级 | 人群 | 典型场景 |
|---|---|---|
| 核心 | 通勤/早餐人群（上班族、学生） | 早上赶时间点一份早餐 |
| 核心 | 不熟悉多步操作的用户 | 想点但不敢用 App / 自助点餐机 |
| 增益 | 替长辈点餐的子女 | 异地给父母点一份早餐送过去 |

## 功能覆盖

覆盖 9 个阶段 × 4 种取餐方式：

| 阶段 | 能力 |
|---|---|
| 认知 | 看门店在售菜单、套餐组成与可替换项、营养成分 |
| 定位 | 搜门店（到店/得来速）、查/建配送地址、**自动判断取餐方式** |
| 权益 | 卡包券（含**日内有效期窗口**）、**门店真正可用券**、可领券、积分与最优兑换 |
| 决策 | **多方案真实计价对比**、券-套餐组合优化 |
| 交易 | 下单（四种取餐方式）+ 下单前闸门 |
| 履约 | 订单状态、取餐方式码 |
| 售后 | 取消订单、历史订单、满意度券 |
| 会员资产 | 积分商城浏览与兑换、商城订单、抽奖与奖品 |
| 特殊场景 | 企业团餐（助餐服务、满减规则）、派对/体验营预约 |

完整功能矩阵与优先级见 [`docs/product-spec.md`](docs/product-spec.md)。

## 安装方法

1. 申请麦当劳 MCP Token：https://open.mcd.cn/mcp
2. 在 WorkBuddy 中配置自定义连接器，填入 `mcp-config.example.json` 的内容，把 `${MCD_MCP_TOKEN}` 替换为真实 Token，并启用
3. 将本仓库复制到 WorkBuddy 技能目录：

```bash
# 用户级（所有项目可用）
cp -r . ~/.workbuddy/skills/mcd-plain-order/

# 或项目级（随仓库共享）
cp -r . <你的项目>/.workbuddy/skills/mcd-plain-order/
```

## 配置

```bash
cp .env.example .env
# 编辑 .env，填入真实 MCD_MCP_TOKEN —— 切勿提交到仓库
```

> ⚠️ `Authorization` 的格式是 `Bearer <Token>`，**`Bearer ` 前缀和后面的空格都不能少**（实测少了会返回 403 + code 400003）。

## 设计标准

本项目对齐《移动互联网应用（APP）适老化通用设计规范》（工信部），核心可验收项：

- 金额三行分列（原价 / 优惠 / 实付）
- 禁用专业词与网络新词（附禁用词表）
- 写操作必须可撤销，回执写明 10 分钟时限
- 无诱导付款、无默认勾选、无营销推送
- Token 与个人数据不入库

完整清单见 [`docs/design-standards.md`](docs/design-standards.md)。

> 诚实说明：本项目**不声称**通过工信部适老化评测，规范在此作为**设计参照标准**使用。

## 边界

不做库存/排班/销量（MCP 无此数据）、不做排队预测、不做品牌对比、不做占座类场景。详见 [`docs/product-spec.md`](docs/product-spec.md) 的「非目标」一节。
